## 0. 结论摘要

1. **一仓三模块**:建立新仓库(建议名 `arcgis-pro-agentkit`),内含三个相互独立、可单独安装使用的模块——A `mcp`(现有 arcgispromcp 全套)、B `guard`(弹窗守护)、C `distill`(模板蒸馏)。一个 `pyproject.toml` 提供 `arcgis-pro-mcp` / `arcgis-guard` / `arcgis-distill` 三个命令;add-in 仍是双击安装的 `.esriAddinX`。
2. **弹窗按需召唤**:取消"启动守护脚本常驻 120 秒"的模式,改为**操作级一次性守卫**:MCP 在即将执行可能触发信任弹窗的操作(RunCode.pyt 等)前自动召唤守卫,操作结束自动收队;操作之间系统里**零守卫进程**。自动点击失败时才召唤第二级警报窗(≥30 秒、置顶、响铃,保持现有用户要求)。
3. **蒸馏按需开启**:蒸馏不再是常驻协作桥的一部分,而是一条**一次性作业流水线**(import → measure → 语义判读 → validate → preview → review → ready)。几何测量、校验、预览、索引全部确定性、无 LLM;语义判读交给调用方助手按技能说明执行,工具本身零 API key。不跑作业时不监听、不扫描、不起服务。
4. **许可证是硬约束**:上游 add-in 为 **AGPL-3.0-or-later**,合并后的仓库必须整体采用 AGPL-3.0,保留 NOTICE 与修改声明。GitHub 公开版**不得携带期刊样本图**及其派生 spec(版权风险),公开库只放自制示例模板。
5. **交付分三期**:M1 守卫按需化(含 add-in 自动召唤)→ M2 蒸馏流水线 → M3 开源发布(版本归一、许可证、双语文档、CI/Release、全新虚拟机演练)。

## 1. 现状盘点(证据锚点)

### 1.1 弹窗机制(当前:独立脚本、常驻轮询)

- 实现:`.claude/arcgis_mcp_runtime/watch_pro_dialog.ps1`(438 行,Windows PowerShell 5.1)。
- 工作方式:启动即进入轮询循环(默认 700 ms),用 UIAutomation 枚举 ArcGIS Pro 顶层窗口与按钮,匹配含「第三方/代码库/third-party/code library」上下文且带「是/允许」按钮的确认框,自动 Invoke;失败则弹置顶提醒窗(至少 30 秒、每 10 秒响铃、每次轮询重新钉顶),并把 Pro 提到前台。
- 生命周期:互斥锁 `Local\ArcGISProDialogWatch_v1`;按墙钟运行(脚本默认 600 s,项目规则用 120 s);Pro 进程消失则退出。
- 使用方式:由 CLAUDE.md 规则要求,在每次 Pro 会话首次运行 RunCode.pyt 前**人工启动**守护脚本。
- 现存问题:
  1. **按墙钟常驻**,绝大多数时间空转;
  2. **依赖人记得启动**,漏启动时信任弹窗会卡住整个流程;
  3. 轮询而非事件触发,没有"操作结束就收队"的概念;

## 3. 弹窗机制重设计:召唤式守卫

### 3.1 设计原则

1. **不常驻**:没有危险操作时,系统中不存在守卫进程、没有任何轮询。
2. **召唤即用**:在可能触发信任弹窗的操作前拉起,操作完成自动收队;召唤是一次函数调用,不是一段人肉仪式。
3. **失败才打扰**:自动点击成功用户无感;只有失败才出现提醒窗(仍 ≥30 秒、置顶、每 10 秒响铃——保持 2026-11-09 既有要求)。
4. **只做一件事**:只点「第三方代码库执行」信任框;其它确认框永不触碰。
5. **可独立使用**:不接 MCP 也能 `arcgis-guard summon` / `arcgis-guard wrap`。

### 3.2 生命周期与状态机

三级生命周期:

- **L0 静默**(默认态):无进程。
- **L1 守卫**(操作级,一次性):被召唤 → ready 握手 → 盯弹窗 → 收队退出。
- **L2 警报窗**:仅 L1 自动点击失败时召唤,≥30 秒后收起,随 L1 退出。

```
             summon(token)
  IDLE ─────────────────────► ARMING
   ▲                            │ 写 ready.json(≤2 s)
   │                            ▼
   │                          ARMED ◄───────────────┐
   │                            │ 检测到信任弹窗       │ 点击成功且弹窗消失
   │                            ▼                   │
   │                         HANDLING ──────────────┘
   │                            │ 点击失败/无按钮
   │                            ▼
   │                      ALERTING(L2 警报窗 ≥30 s)
   │                            │ 用户解决 / 警报超时
   │                            ▼
   │   全部 token 已 settle 且宽限期(3 s)无新弹窗
   └──────────────────────── EXITING ◄── 绝对超时(op 180 s / manual 600 s)或 Pro 退出
```

### 3.3 召唤协议(文件令牌握手,语言无关)

- 守卫启动参数:`-Token <token> -Scope op|manual -TimeoutSeconds N [-AlertOnly] [-ConfigPath ...]`。
- 会话目录:`%LOCALAPPDATA%\ArcGIS-AgentKit\guard\sessions\<token>\`
  - `ready.json` —— 守卫写入:`{pid, armed_at, scope, engine_version, pro_pids[]}`;召唤方轮询 50 ms、最多等 2 s。
  - `settle` —— 召唤方在操作结束(成功或失败)时写入;守卫收到后进入 3 s 宽限期,无弹窗则退出。
  - `result.json` —— 守卫退出前写入:`{detected, clicked, alerted, resolved, exit_reason, events[]}`。
- **单守卫多令牌**:互斥锁 `Local\ArcGISProDialogWatch_v2` 保证只有一个引擎进程;后续召唤把 token 追加到 `active.json`,守卫在**所有** token 都 settle 且无未解决弹窗后才退出。
- **失败降级(fail-open,但不放宽安全边界)**:召唤方 2 s 内拿不到 ready → 操作照常执行,结果里附红字警告("守卫未就绪,弹窗需人工点击"),并写日志。绝不因自动化失败而阻塞用户的业务。
- **兼容**:直接 `powershell -File guard.ps1` 仍可用,参数向后兼容旧脚本(`-DurationSeconds/-AlertOnly/-SelfTest/-NotifyTest`),老规则文件可平滑迁移。

### 3.4 检测机制:事件优先 + 兜底轮询

- **主通道**:UIA 事件 `WindowOpened` / `StructureChanged`(按 Pro 进程 PID 过滤),弹窗一出现立即处理,正常时 CPU 占用≈0。
- **兜底**:仅 ARMED 状态下保留低频轮询(400 ms 处理中 / 1.5 s 宽限期),对抗 UIA 事件偶发丢失;若目标机上事件通道不稳定,自动退化为 400 ms 纯轮询——**只影响被召唤的几秒钟,不再影响全天**。
- **判定规则外置** `guard.schema.json`,与代码解耦、可单测:

```json
{
  "match": {
    "strong": ["第三方", "代码库", "third-party", "code library"],
    "weak":   ["Python"],
    "affirm_buttons": ["是", "允许", "Yes", "Allow"],
    "tallow": ["允许", "执行", "trust", "信任", "allow"],
    "deny":   ["覆盖", "删除", "移除", "overwrite", "delete", "replace"]
  },
  "alert":  { "min_seconds": 30, "sound": true, "position": "top-right", "style": "mac" },
  "limits": { "arm_ready_ms": 2000, "settle_grace_s": 3,
              "op_timeout_s": 180, "manual_timeout_s": 600,
              "poll_active_ms": 400, "poll_grace_ms": 1500 }
}
```

- `min_seconds` 低于 30 一律按 30 执行(代码内硬校验,防配置误改)。

### 3.5 与 MCP 的集成(消灭"人工启动守护"规则)

- add-in 新增 `Bridge/GuardClient.cs`:
  - `RunToolboxToolAsync`(`GeoprocessingCommands.cs:217`)执行体外包一层:
    ```
    using (GuardLease lease = GuardClient.Arm("run_python_toolbox_tool"))
    {    ...原有执行...    }   // finally 中 Settle
    ```
  - 默认只为 `run_python_toolbox_tool` 召唤;`run_geoprocessing_tool` 命中 `.pyt/.atbx/.tbx` 路径时也召唤(可配置名单)。
  - 引擎位置:优先 `%LOCALAPPDATA%\ArcGIS-AgentKit\guard\engine\guard.ps1`,其次 add-in 安装目录旁;找不到 → 不召唤,结果附警告。
- 新增 MCP 工具(供非 GP 场景,如 ENVI→Pro 导入流程):
  - `guard_summon(scope="op", timeout_s=120, alert_only=false)` → 返回 token;
  - `guard_status()` → 活动会话、最近结果、引擎版本。
- **行为不变性**:未装 guard 时 MCP 一切照旧;装了之后只是"该弹的时候有人替你点",安全边界不因自动化而放宽。

### 3.6 独立 CLI

```text
arcgis-guard summon [--scope op|manual] [--timeout 120] [--alert-only]
arcgis-guard wrap -- <任意命令>      # 召唤 → 执行 → 收队,透传子进程退出码
arcgis-guard status                  # 是否有守卫在跑、各 token 状态
arcgis-guard test --notify           # 警报窗可见性测试(≥30 s 自动关闭)
arcgis-guard self-test               # 扫描当前 Pro 窗口/按钮,输出诊断
arcgis-guard doctor
```

`wrap` 是给"不经过 MCP"的场景准备的(例如用户自己写的 PowerShell 批处理里跑 RunCode.pyt),一条命令同时获得按需召唤与自动收队。

### 3.7 安全边界(不可放宽,写进代码与测试)

| 条件 | 动作 |
|---|---|
| 强上下文(第三方/代码库/…) + 「是/允许」按钮 | 点击,并以证据文本记审计日志 |
| 仅弱上下文(Python + 允许/执行/信任词) | 点击;日志标注 weak-match |
| 命中 deny 列表(覆盖/删除/…) | **只警报,绝不点击** |
| 非 Pro 进程的窗口 | 不处理 |
| 按钮找不到 / Invoke 失败 | 升级 L2 警报窗 |
| 无法判定 | 不点击(默认安全) |

每次决策写 JSONL:窗口标题、文本摘录(≤400 字符)、命中规则 id、按钮清单、动作、结果。审计日志同时满足排障与"为什么点了"的追溯。

### 3.8 新旧对照

| 维度 | 现 watch_pro_dialog.ps1 | 新 guard |
|---|---|---|
| 生命周期 | 墙钟常驻(120–600 s) | 操作级一次性,结束后零进程 |
| 启动方式 | 人工按规则启动 | MCP 自动召唤 / CLI 一条命令 |
| 检测 | 700 ms 轮询 | UIA 事件优先 + 兜底轮询(仅被召唤期间) |
| 警报窗 | 硬编码外部 MacDialog 路径(已失效回退黄窗体) | 内置渲染库,无外部依赖 |
| 规则 | 硬编码在脚本里 | 外置 JSON,可覆盖、可测试 |
| 与 MCP 关系 | 无 | add-in 内嵌客户端,自动 arm/settle |
| 日志 | 纯文本 | JSONL 事件流(含证据文本) |
| 可开源 | 否(个人路径) | 是(零个人路径) |

### 3.9 验收标准(M1)

1. 连续 10 次 `run_python_toolbox_tool` 调用:0 次人工点击;每次调用之间任务管理器无 powershell 守卫进程。
2. 人为制造自动点击失败(临时把 affirm 按钮名改错):警报窗出现,≥30 s、置顶、每 10 s 响铃,解决后自动收起。
3. 用「覆盖输出」确认框回归:全程只警报、0 次误点。
4. 击杀守卫进程后继续 MCP 调用:业务照常完成,结果带警告。
5. `arcgis-guard wrap` 包装任意长任务:任务结束 3 s 内守卫退出,`result.json` 完整。

## 4. 蒸馏机制重设计:按需模板蒸馏

### 4.1 设计原则

1. **不常驻**:没有作业时,不监听 inbox、不扫描目录、不起任何服务;inbox 只是普通文件夹。
2. **一次作业一条命令**:可分步、可断点续做、每步幂等(以样本图 sha256 为幂等键)。
3. **确定性优先**:几何测量、schema/一致性校验、预览渲染、索引维护全部无 LLM、可测试、结果可复现。
4. **不绑定模型**:只有"语义判读"一步由使用者的助手按 `skills/template-distill/SKILL.md` 完成(Claude/Codex/其它皆可),工具本身零 API key、零外呼。
5. **质量门**:spec 必须通过 schema 校验 + 几何一致性校验 + 人工 review 才能 `ready`,半成品模板无法流入制图。

### 4.2 作业状态机与幂等

```
imported ──measure──► measured ──patch(语义字段)──► analyzed
   ▲                      │                          │
   │(--force 重来)        │                          ▼
   └──────────────────────┴──────────── validate ◄────┘
                                          │ review + approve
                                          ▼
                                        ready ──apply──► 制图任务上下文
```

- 作业单:`%LOCALAPPDATA%\ArcGIS-AgentKit\jobs\<tpl-id>.json`,记录 `{image_sha256, steps: {measure: {tool_version, at, output_hash}, ...}}`。
- 重跑时输入未变 → 跳过已完成步骤;`--force` 强制重做。中断(关机/报错)后重跑即可续做。

### 4.3 确定性通道(无 LLM,可直接交付)

| 命令 | 作用 |
|---|---|
| `distill import <image> --name --tags [--width-in]` | 哈希去重、图片入库、按 schema v1.1 生成 draft 骨架(改进现有 gateway 的骨架) |
| `distill measure <id> [--width-in]` | 移植 `measure_figure.py`:图幅裁切、长宽比、强横/竖线;新增:主色提取(palette_top)、dpi 推断;回写 `measured` |
| `distill validate <id>` | schema 校验 + 几何一致性(`map_frame ⊂ canvas`、图例/比例尺/指北针不越界、字号单调、颜色合法、measured 与 canvas 宽度容差 ≤3%) |
| `distill preview <id> [--out png]` | 把 spec 画成线框预览(白底画布 + 各分区矩形 + 标注),与样本图并排输出,供 review |
| `distill list/get/export/import-bundle` | 模板库原子维护;整包导出(zip:spec+图片+index 条目),便于社区分享 |
| `distill apply <id> --plan plan.json` | 并入制图任务上下文(`context/template.json` + plan 引用),与现有 executor 对接方式兼容 |
| `distill inbox [--list|--process-new]` | 一次性扫描 inbox;不监听 |

### 4.4 语义通道(Skill 驱动)

- `skills/template-distill/SKILL.md` 给助手的作业指导:
  1. 先 `import` + `measure`,**禁止手改 measured 数值**;
  2. 看样本图与 measure 结果,产出 `regions[]`(归一化版式分区)、`legend` 样式、`palette` 语义、`typography` 层级、`locator_insets`、`pitfalls[]`(结构化易翻车点);
  3. 用 `distill patch <id> --file spec.patch.json` 提交(走校验合并,不直接改库文件);
  4. `validate` 全绿 → `preview` 给用户看 → 用户确认后 `review --by ...` → `approve` 置 ready。
- 可选三方评审适配器:`review --meeting`(仅当检测到本机装有协作桥时启用;**开源默认关闭**,不构成依赖)。

### 4.5 与 MCP / 制图流程的集成

- 新增 MCP 工具(薄封装,底层调 `arcgis-distill` CLI):`template_list / template_get / template_import / template_measure / template_patch / template_validate / template_apply`,以及返回预览 PNG 的 `template_preview`。
- **蒸馏永远不自动触发**:助手只有在用户明确说"把这张图蒸馏成模板"时才调用;与"需要时再开启"一致。
- 出图链路:选模板(`template_list`)→ `template_apply` 写入任务上下文 → 按模板规范制图 → 导出 → 人工验收(沿用现有 arcgis-pro-mapping 技能流程)。

### 4.6 模板库与 schema v1.1(向后兼容)

- 库布局:`library/{schema.json, index.json, images/, specs/, inbox/}`——与现有 gis-gateway 完全兼容,现有 5 个模板原样可读。
- schema v1.1 **只增不改**:
  - `regions[]`:`{name, role, x, y, w, h, notes}`(归一化 0–1);
  - `measured.palette_top[]`:主色及占比;
  - `pitfalls[]`:`{issue, check, severity}`(把 notes 里的经验变成可执行检查);
  - `review{}`:`{by, date, decisions[]}`(质量门凭证)。
- 公开库:仅 `library/examples/` 中的自制示例模板(见 §2.4 版权约束);用户私有库在本地,`.gitignore` 隔离。

### 4.7 验收标准(M2)

1. 用 3 个期刊样本重跑蒸馏:`measure` 与旧 spec 的 `measured` 块误差在容差内;`validate` 全绿;`preview` 目检与样本版式吻合。
2. 全程无守护进程/服务残留;中断后重跑跳过已完成步骤(`--json` 可见 skipped 列表)。
3. 在未安装 ArcGIS 的机器上:`import/measure/validate/preview/list/export` 全部可用。
4. 故意提交越界 legend:validate 拒绝并给出可读原因;强制 approve 需显式 `--force` 且写入 review 记录。

## 5. 三个端到端场景

### 场景一:助手跑 RunCode.pyt,弹窗全自动(无人值守)

1. 用户:"把这个图层按模板导出 PDF"。
2. 助手调用 `run_python_toolbox_tool` → add-in `GuardClient.Arm` 召唤守卫(token t1)→ 2 s 内 ready。
3. GP 执行,Pro 首次弹「第三方代码库」信任框 → 守卫 UIA 事件触发 → Invoke「是」→ 弹窗消失,日志记 resolved。
4. GP 返回 → `Settle(t1)` → 3 s 宽限无新弹窗 → 守卫退出。**调用之间系统里没有任何守卫进程。**

### 场景二:一张期刊图蒸馏成模板(按需开启)

1. 用户把截图放进 inbox,说"蒸馏这张图,叫《研究区总览图》"。
2. 助手按 SKILL:`arcgis-distill import` → `measure` → 对照原图写 patch(regions/legend/palette/pitfalls)→ `validate` → `preview` 给用户看 → 用户点头 → `review --by 柳皓文` → `approve`。
3. 全程一次性命令,结束即无残留;spec 入本地库,`index.json` 原子更新。

### 场景三:用蒸馏出来的模板出图(闭环)

1. 用户:"用《研究区总览图》模板给这次的数据出图"。
2. 助手 `template_list` → `template_apply --plan` → 按 spec 的版式/字号/图例规范在 Pro 中制图 → 导出 → 按既有技能流程自检 → 弹窗人工验收(是=结束/否=继续修改)。

## 8. 关键取舍记录(ADR)

| # | 决策 | 取舍理由 |
|---|---|---|
| ADR-1 | 单仓三模块,不做三个独立仓库 | 版本联动、一次发布、一个安装故事;模块仍可单独 pip 安装使用 |
| ADR-2 | 守卫引擎保留 PowerShell 5.1,不重写为纯 Python | 现有 UIA Invoke 在 Pro 3.7 实测可靠;PS 5.1 Windows 自带、零依赖;C#/Python 只做召唤客户端,职责清晰 |
| ADR-3 | 检测以 UIA 事件为主、兜底轮询 | 事件通道在部分机器可能丢事件;兜底轮询只在被召唤的几秒内运行,兼顾可靠与"不常驻" |
| ADR-4 | 守卫不内嵌进 add-in 进程 | 外部进程隔离:Pro 模态弹窗时外部进程更稳、可独立测试、可独立于 MCP 使用 |
| ADR-5 | 蒸馏不内置任何 LLM/API | 开源无密钥门槛;语义判读由调用方助手按 SKILL.md 完成,效果随助手升级而升级 |
| ADR-6 | 强制 AGPL-3.0 | 上游许可证约束,无替代方案;公开源码即合规,且防止闭源商用不分发源码 |
| ADR-7 | 模板库与公开示例分离 | 规避期刊图版权风险;用户私有资产默认不出本机 |
| ADR-8 | MCP 工具薄封装 CLI,而非在 C# 里重写业务 | 一份实现两处复用;guard/distill 可脱离 MCP 单测 |
